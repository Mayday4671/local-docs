# 0.7.1 Word 编辑与提示修复验收

日期：2026-09-27。

## 问题及修正

Word 点击“编辑内容”已进入页面编辑，但标题等普通文字不能输入。原因是旧逻辑对整个段落查找 `w:tab`，把段落属性内的制表位配置当成了正文中的制表符，误判为复杂内容。修正后仅按正文内容判断受限节点，段落格式保持原样。普通空白段落允许输入，保存时增加文字节点并保留段落属性、表格和其他结构。进入编辑模式后自动聚焦第一个可编辑正文位置；不支持的区域使用准确的范围提示。

底部成功消息原先没有关闭计时。现在显示约 3 秒后关闭，连续同文案操作重新计时，手动关闭可用；旧定时器不会关闭后来的消息。错误和处理中状态仍保留，不被成功提示计时关闭。

## 针对反馈文档的诊断

在本机以只读方式定位用户反馈的 DOCX，仅输出结构统计，没有将文档正文、原件副本或截图保存到代码及验收资料中。正文存在 53 处带制表位属性的段落、274 个无文字节点的空白段落，实际正文制表符为零，未设置文档保护。该结构能直接解释标题等被误判只读的问题。

用修复后的代码在内存中检查同一文档，483 个段落字段中 482 个可编辑，274 个空白位置可编辑；对标题与空白位置进行内存修改后重新读取成功。其他文档部件保持相同，原对象文件 SHA-256 未改变。未修改用户数据库、实际文档或正在使用的应用；没有将此检查等同于对整份真实文档逐段进行人工界面验收。

## 回归验证

- 62 项单元测试通过，新增段落制表位误判、空白表格段落输入 / 清空 / 再输入、正文实际制表符 / 换行 / 域仍保持只读。
- 新增合成 Word 样本：带制表位与居中格式的标题、表格文本、空白表格段落、图片和页眉。它只复现结构，不含用户资料。
- `word-edit-fix-smoke.mjs` 通过实际 Electron 鼠标与键盘完成编辑、保存和重新加载，验证提示 3 秒消失、连续保存重新计时、手动关闭、错误保留，以及模拟原生保存对话框等待期间“正在处理”不会超时消失。
- `verify-word-edit-fix.py` 用独立 python-docx 复读实际导出，确认标题、原空白单元格、制表位与图片可读取，其他部件字节未改。
- 类型检查、格式检查、生产构建和 NSIS 打包通过。包内 EXE 完整回归见 [Windows 交付说明](Windows交付说明.md)。

未更改数据库结构；没有覆盖安装或关闭用户窗口。完整字体排版、正文制表符 / 换行编辑、复杂域与修订、公式计算等仍沿用已说明的限制。
