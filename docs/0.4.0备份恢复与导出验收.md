# 0.4.0 备份、恢复与分类导出

日期：2026-09-27。此版继续提供 Windows EXE，保留右上角主题按钮。Word / Excel 在正式应用中仍为只读。

## 使用入口

- **设置 → 创建备份**：选择数据目录之外的位置，生成 `.localdocs-backup` 文件。
- **设置 → 选择备份**：先校验并显示备份时间、文件数量、回收站、分类和历史数量。取消不会替换当前库；确认后先备份当前库，再整体恢复，不合并两份库。
- **文件列表右上角菜单 → 导出此分类（含子分类）**：导出当前分类的整个子树，包含空分类，不受当前搜索或类型筛选影响。
- **设置 → 导出整个文档库**：输出普通文件夹和 `导出清单.json`，保留当前文件，不包含回收站和历史。文件同名时添加序号，不覆盖原件。
- 操作结果显示保存位置，可直接在文件管理器中查看。进行中的任务显示阶段与数量，提交恢复前可以取消。

## 保存与恢复机制

备份是一份 ZIP 容器：版本化 JSON 清单与按 SHA-256 标识的原始对象。清单保留分类、文档 ID、名称、时间、收藏、标签、备注、回收站状态、历史顺序及主题。搜索与 Office 预览缓存属于派生数据，不进入备份；恢复后重新建立。

备份在同一 SQLite 事务中采集元数据，再流式校验并打包不可变内容。备份输出以独占方式创建，不覆盖已有文件；成功前刷新到磁盘。普通库操作与维护操作串行，恢复前后的请求通过代次区分，避免旧阅读或搜索结果写回恢复后的库。

恢复只接受清单和合法哈希对象路径，拒绝路径穿越、重复、加密、符号链接、未知文件、未来格式版本、循环分类、孤立引用、大小和内容摘要不符。暂存后再次校验，文件内容落盘后才用单个 SQLite 事务替换元数据；失败时回滚全部元数据，已有对象不被覆盖。

恢复前的自动备份位于 `%APPDATA%/local-docs/recovery-backups/`（自定义测试数据目录时随该目录变化）。自动备份失败不会继续恢复。该备份可再次通过“选择备份”恢复。它保存在同一磁盘，不能代替另存到其他介质的日常备份。

## 实际验证

- `npm test` 共 **32 项通过**，其中新增 **12 项**覆盖备份与恢复。
- 使用两份独立文档库进行恢复，验证分类层级、历史版本顺序、回收站、标签、备注、收藏、打开时间和主题完全保留。
- DOCX、XLSX、`.md`、`.markdown` 备份后恢复并导出，与输入原始字节逐一比较相同；UTF-8 BOM、换行保留。
- 分类子树、空分类、仅大小写不同的名称、文件与目录同名均通过；导出排除回收站。
- 损坏 / 缺失 / 多余对象、重复 ZIP 条目、路径穿越、未来格式、循环分类、无效引用、暂存篡改均被拒绝。
- 注入恢复事务失败，原库完整回滚并能重启读取；恢复前备份生成失败时原库不变。备份源损坏会终止输出，取消流式备份后清除未完成文件。
- 实际 Electron 与包内 EXE 验证设置入口、预览 / 取消、恢复确认、恢复前备份、分类导出、Office 索引重建、失败提示及重启保留。
- 1536 px / 1000 px 窗口检查；浅色恢复确认和深色设置截图已检查。相关桌面流程无 HTTP/HTTPS 请求、无未捕获页面异常。
- 其余基础、Office 阅读、原型界面、格式与主题四组包内 EXE 回归通过。

## 边界与后续

备份格式 v1 当前限制：单个对象 100 MiB、Markdown 5 MiB、总对象内容 10 GiB、清单 64 MiB，各类记录 / 对象最多 100,000，分类深度最多 128。目录导出对过长路径明确报错并清理本次未完成目录，可选择更浅位置或分分类导出。

备份未加密。恢复为整体替换，不提供合并；不存在定期备份或备份自动清理。成功恢复后，旧的无引用对象暂不自动删除；异常退出留下的暂存文件也尚无设置页清理入口。大库性能、实际磁盘耗尽 / 断电和 Windows 覆盖安装仍需专项验收，当前故障测试不等价于这些完整环境测试。

换机恢复已验证，应用内选择新存储盘尚未实现；Office 内置编辑、分类改名 / 移动 / 删除、文件夹导入和自动保存仍在后续计划中。
