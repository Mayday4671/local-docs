## 已明确的产品方向

1. 软件名“我的文档库”；目录、仓库和 npm 包名均为 `local-docs`。
2. React 和 Electron 放在一个工程中；采用 TypeScript、SQLite，不额外建设 Spring Boot、MySQL 或云端管理后台。
3. 个人使用、无需登录、离线工作，用户主动添加文件；不扫描电脑，不监控原目录。
4. 导入的是文档库副本，不能修改或删除原位置文件。
5. 主界面为左侧分类、中间列表、右侧可收起预览，顶部搜索、添加、新建。
6. 目标包含 DOCX、XLSX、Markdown 的应用内查看与编辑；外部程序打开只能是补充，不能替代 Office 内置编辑。
7. 目标包含多级分类、标签、备注、收藏、最近使用、全文搜索、导出、回收站、版本、备份恢复和迁移。
8. 删除分类不能顺带删除文件；普通删除进入回收站；保存与覆盖要保护历史内容。
9. 中文搜索必须覆盖一两个汉字的查询，不能只测长词。

## 后续开发顺序

### 1. Office 引擎技术验证（完整 MVP 的前置条件）

以“安装 EXE → 打开 → 应用内修改 → 保存”为用户路径。候选引擎必须验证：授权与费用、离线运行、是否需要额外服务、Windows 安装体积、启动生命周期、保存回写和异常恢复。

准备有代表性的 DOCX / XLSX：中文与字体、图片、页眉页脚、分页、表格；工作簿含多个工作表、合并单元格、公式和格式。对比编辑前后文件，确认实际文件保存和二次打开。引擎未通过验证时，不能将整个文档编辑目标标记完成。

### 2. 导入与整理

多级分类及改名/移动/删除规则、文件夹导入保留层级、拖放、重名与重复文件策略、导入进度/取消/失败重试。将大文件处理迁移至后台任务；补齐标签和备注。

### 3. 编辑与检索

Markdown 附件与受保护的自动保存；接入验证通过的 Office 引擎；提取 Word 正文和真实 Excel 单元格位置；FTS 与短中文回退；摘要、高亮、命中定位及搜索返回状态。

### 4. 数据带走与恢复

按分类导出普通目录、批量导出、Markdown 附件一并带走。区分“导出文件”和“备份文档库”；实现一致性备份、校验、恢复预览与回滚、存储迁移、索引重建。

### 5. Windows 交付与完整验收

NSIS 安装/升级/卸载、数据目录保留、系统权限、异常关闭恢复、版本存储策略、大数据量与 Office 格式保真验收。根据完整需求重新建立验收清单。
